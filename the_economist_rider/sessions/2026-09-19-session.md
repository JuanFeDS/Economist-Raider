# Sesión — 2026-09-19

## Sesión 1

### Tema principal
Construcción completa de "Sala de Lectura" — app para leer, traducir y anotar PDFs de estudio — desde un visor simple hasta una aplicación multiusuario con autenticación, desplegada en GCP bajo dominio propio.

### Decisiones tomadas
- Traducción: Argos Translate (offline, gratis) en vez de transformers/Helsinki-NLP, tras benchmark real (~6x más rápido, calidad similar, ambos requieren PyTorch igual).
- Despliegue multiusuario con Supabase (Auth + Postgres, tier gratuito) + GCP Cloud Run, partido en dos servicios (`web` liviano, `traductor` con PyTorch) para mantener costo cercano a cero — Cloud Tasks conecta ambos porque Cloud Run no garantiza CPU fuera de un request activo.
- Dominio: subdominio `tools.juanfeds.com` (mapeo nativo de Cloud Run, gratis) en vez de `juanfeds.com/tools/...` (hubiera requerido migrar el DNS a Cloudflare).
- Subrayado de texto: selección libre estilo Kindle, no por párrafo completo.
- Exportar notas: a `Estudio/papers/<nombre>-notas.md`, no dentro de `modulos/`, para no tocar la estructura curada de `notas.md` por módulo.
- Repo de git creado solo dentro de `Estudio/tools/app/`, no en la raíz del proyecto.

### Trabajo realizado
- Iteración completa del producto: visor PDF.js → extracción de texto (PyMuPDF + heurística de reconstrucción de párrafos) → comparación de traductores → app Flask completa (biblioteca con categorías estilo VS Code, posición de lectura persistente, subrayado + comentarios, exportación a Markdown).
- Rediseño visual completo tras feedback de "workslop" (cajas genéricas repetidas) — sistema de 4 paletas (Blanco/Papel/Azul/Terminal), sin bordes uniformes repetidos.
- Migración a multiusuario: proyecto Supabase `pdf_reader`, esquema con RLS (`documentos`, `subrayados`, `trabajos_traduccion`, luego `trabajo_parrafos`), Auth por magic link.
- División de `server.py` en `web/app.py` (CRUD liviano) y `traductor/app.py` (Argos/PyTorch), con estado de trabajos en Postgres en vez de memoria.
- Dos bugs reales encontrados y arreglados: (1) traducciones duplicadas corriendo en paralelo tras recargar la página; (2) reenvío del arreglo completo de párrafos en cada actualización de progreso (normalizado a tabla `trabajo_parrafos`).
- Instalación y autenticación de `gcloud` CLI, proyecto GCP `sala-lectura-economist`, facturación reactivada, alerta de presupuesto (~1 USD), despliegue de ambos servicios en Cloud Run (`us-central1`), cola de Cloud Tasks.
- Bug de producción arreglado: modelo de Stanza no precargado en la imagen del traductor (causaba error de MD5) — se fuerza una traducción de prueba durante el build.
- Mapeo de dominio `tools.juanfeds.com` a Cloud Run (verificación de dominio vía Search Console + CNAME).
- Limpieza de imágenes viejas en Artifact Registry (~7GB → ~3.5GB) + política de limpieza automática.
- Repo git en `Estudio/tools/app/` con 3 commits vía `/make-commits`.

### Conclusiones
- Argos Translate no entra en el tier gratuito "Always Free" de GCP (`e2-micro`, 1GB RAM) por el peso de PyTorch — esto fue lo que forzó la arquitectura de Cloud Run (pago por uso) en vez de una VM siempre encendida.
- Costo real esperado de todo el despliegue: prácticamente $0/mes, salvo un cargo pequeño (~$0.30/mes) por almacenamiento de imágenes en Artifact Registry, ya mitigado con limpieza automática.
- El flujo `gcloud auth login --no-browser` / `--no-launch-browser` tuvo bugs en esta versión; el flujo default (navegador + callback local) funcionó bien al estar en la misma máquina.
